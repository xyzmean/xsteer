# Xsteer под Android

Клиент xsteer для телефона, планшета и телевизора: список туннелей, правка настройки, чтение QR,
исключение приложений, плитка в шторке, режим «всегда включён», журнал.

**Это переделанный клиент WireGuard для Android** (`github.com/WireGuard/wireguard-android`,
Apache 2.0). Взято приложение целиком; заменён движок. Права на исходный код принадлежат его
авторам, и шапки файлов с их правами оставлены на месте — так требует лицензия и так честно.

**Ничего из этого ещё не запускалось на живом устройстве.** Собирается и проверяется стендами
разбора настройки, но ни одного пакета через настоящий телефон не прошло.

## Что заменено

| было | стало |
|---|---|
| движок нативной библиотекой `libwg-go`, вызовы через JNI | `xsteer.aar` из `mobile/`, собранный gomobile |
| настройка уезжала в движок строкой uapi | уезжает текстом — тем же, что читает консольная половина |
| счётчики по пирам из `wgGetConfig` | снимок состояния JSON: у звезды собеседник один — хаб |
| два движка на выбор: модуль ядра под root и своя половина | один: модуля ядра у протокола нет |
| свой обновлятор с чужого сервера, пожертвования, установщик утилит | убраны |

Точка стыка осталась та же и единственная: система строит туннель через `VpnService.Builder` и
отдаёт **дескриптор**, дальше им распоряжается половина на Go (`tun.FromFD`). Пакеты не пересекают
границу языков вовсе — их читает и пишет тот же код, что на обычном Linux.

## Что добавлено сверх исходного

- **Ключ `SNI`** в настройке: имя, которое уйдёт в ClientHello. Есть в правке, виден в
  подробностях, переживает круг «прочитали — записали».
- **Ссылка `xs://`**: открывается нажатием из мессенджера, принимается из «поделиться» и из QR.
  Разбирает её движок и отдаёт обратно текстом — второго разбора того же формата в приложении нет.
- **Подпись ключом проекта** из окружения, иначе новая сборка не встаёт поверх прежней.

## Чем это проще iOS

**Прав и платного участия не нужно.** Достаточно объявить службу `VpnService`, и система сама
спросит согласие у человека при первом подключении. Готовый `.apk` ставится как есть.

**Устройство — настоящий дескриптор**, а не объект с вызовами. Поэтому здесь нет ни очереди, ни
склейки, ни счётчиков потерь: всё это на iOS нужно ровно потому, что там дескриптора нет.

## Как собрать

```sh
android/build-aar.sh            # gomobile bind -> android/tunnel/libs/xsteer.aar
cd android && ./gradlew assembleRelease
```

Нужны Go, Android SDK и NDK. Mac не нужен. То же самое делает `.github/workflows/android.yml` на
каждый коммит; готовый `.apk` попадает на страницу установки (см. `site/`).

## Подпись

Android ставит новую версию поверх прежней только тогда, когда обе подписаны одним ключом, а
отладочный ключ на чистом бегунке каждый раз новый. Ключ проекта заводится один раз:

```sh
keytool -genkeypair -v -keystore xsteer.jks -alias xsteer -keyalg RSA -keysize 4096 -validity 10000
base64 -w0 xsteer.jks           # это значение — в секрет ANDROID_KEYSTORE_BASE64
```

| секрет | что это |
|---|---|
| `ANDROID_KEYSTORE_BASE64` | файл `xsteer.jks`, закодированный base64 |
| `ANDROID_KEYSTORE_PASSWORD` | пароль хранилища ключей |
| `ANDROID_KEY_ALIAS` | имя ключа внутри хранилища (по умолчанию `xsteer`) |
| `ANDROID_KEY_PASSWORD` | пароль ключа, если отличается от пароля хранилища |

Без них сборка идёт с отладочным ключом и остаётся рабочей — но страница установки в этом случае
говорит прямо: чтобы поставить новую сборку, прежнюю придётся удалить.

## Устройство

```
android/
  tunnel/          библиотека: разбор настройки, ключи, мост к движку
    .../backend/GoBackend.java    здесь и заменён движок
    .../config/                   модель настройки (сюда добавлен SNI)
  ui/              приложение: список, правка, подробности, настройки, QR
  build-aar.sh     сборка половины на Go в tunnel/libs/xsteer.aar
```

## Что проверено

`cd mobile && go test ./...` — мост; `./gradlew :tunnel:testDebugUnitTest` — разбор настройки
(стенды из исходного проекта, включая образцы с ошибками). Часть на Kotlin и сам туннель на
устройстве не запускались.
