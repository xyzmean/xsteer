# Страница установки

Отсюда человек забирает приложение: `.apk` под Android и `.ipa` под iOS, а заодно видит, чем
ставится хаб на сервер. Страница одна на все платформы.

## Почему одна, а не по одной на платформу

У хранилища **один** сайт, и всякая выкладка заменяет его целиком. Публикуй каждая сборка своё,
они стирали бы работу друг друга: страница iOS исчезала бы при первом же коммите в Android, и
заметить это можно было бы только с телефона. Поэтому сборки только собирают, а выкладывает одно
описание — `.github/workflows/pages.yml`.

## Что здесь лежит

| файл | что это |
|---|---|
| `build-site.py` | собирает страницу: подставляет метки, считает суммы, рисует QR |
| `index.html.in` | страница целиком; разделы платформ подставляются метками |
| `block-android.html.in`, `block-android-none.html` | раздел Android: со сборкой и без неё |
| `block-ios.html.in`, `block-ios-none.html` | то же для iOS |
| `manifest.plist.in` | манифест установки для iOS (`itms-services`) |
| `icon-512.png`, `icon-57.png` | картинки страницы и манифеста |

## Собрать и посмотреть глазами

```sh
python3 site/build-site.py --out /tmp/site --base https://example.github.io/xsteer
python3 -m http.server -d /tmp/site 8000
```

Без `--apk` и `--ipa` получится страница, у которой оба раздела говорят «сборки пока нет» — это
законное состояние, а не поломка: раздел без сборки честнее ссылки, ведущей в никуда.

С файлами:

```sh
python3 site/build-site.py --out /tmp/site --base https://example.github.io/xsteer \
    --apk путь/к/xsteer.apk --apk-version 42 --apk-signed yes
```

Незакрытая метка `@ИМЯ@` в готовой странице — отказ сборщика, а не предупреждение: страница с
ней молча не работала бы, указывая ссылкой на `@APK@`.
